## Поведение

- Сначала первая попытка для всех доступных локаций/протоколов; до завершения этого прохода повторов нет. До **8** проверок одновременно; освободившийся исполнитель сразу берёт следующую локацию. Блокирующие вызовы libbox выполняются вне Main.
- Первая попытка ограничена **5 с**: один HTTP-адрес, native timeout **4,5 с**, запас RPC **250 мс** и ожидание подтверждения завершения отменённого вызова **100 мс**.
- После первого прохода — общая пауза **2 с** и отдельная очередь подтверждений. Только завершившиеся сетевые проверки без ответа попадают в эту очередь. Повтор ограничен **9 с**, начинается с другого HTTP-адреса; native timeout **4 с** на адрес. Исправно ответившие локации автоматически не перепроверяются.
- Общий предел запуска — **60 с**. По его истечении готовые результаты сохраняются, оставшиеся получают нейтральное «Не завершено» с объяснением ограничения времени. Это не доказательство недоступности сервера. Ручная остановка имеет отдельный итог.
- В панели отдельно показаны первый проход и подтверждения; счётчики «проверяются / ожидают / ждут повтора», прошедшее время и предел. В строке видны номер попытки и её прошедшее/доступное время. Часы обновляются каждую секунду, даже когда ответов нет.
- Сохраняются полный повтор, повтор только неуспешных/незавершённых, время успешных результатов, стабильный порядок списка и выбор сервера. Старые результаты ядра не выдаются за свежие.

## Ошибки и отмена

- Общий пул допускает не более **8 фактически выполняющихся блокирующих Java/JNI-вызовов** между экранами и запусками. Отмена ожидания не освобождает занятый native-вызовом поток. Отменённые задания, которые ещё не начали выполняться, удаляются из очереди пула и не создают клиентов позже.
- Закрывается только собственный CommandClient проверки, в отдельном пуле; общий клиент, VPN, профиль и выбранный узел не останавливаются.
- Если завершение native-запроса после таймаута не подтверждено, строка получает «Ошибка проверки» и пояснение о незавершённом запросе. Автоматического повтора нет. Задание, которое не удалось начать из-за занятых исполнителей, тоже не считается отсутствием ответа сервера.
- На обоих уровнях результат `null` (завершённая проверка без ответа) отделён от истечения внешнего дедлайна. Задержка Main во время отмены не превращает незавершённый запрос в «Нет ответа» и не запускает дубликат.
- Родительская отмена, общий дедлайн, смена сети/профиля/сессии и закрытие панели сохраняют прежнюю защиту поколений: поздний ответ не перекрашивает закончившуюся проверку в зелёный.
- Успех **0 мс** допустим по контракту libbox. «Нет ответа» появляется только после двух завершённых попыток. Ошибки управления не содержат исходных исключений/конфигурации.

Изменена ручная проверка локаций. Сторож, автовыбор, маршрутизация, состав протоколов и закреплённое ядро `v1.14.0-lx.29` сохранены. Ограничение Java/JNI-пула не доказывает остановку внутренних Go-операций ядра.
