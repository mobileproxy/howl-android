# Howl Android: подготовка настоящей ротации подписи

20.10.2026. Ветка `android/signing-rotation`, основа `85273d77f7c54df348ea1a6fd5fba4dfb8541704`. Текущий этап: локальная подготовка завершена; перед настоящей lineage и CI требуется разрешение владельца на передачу нового приватного ключа и параметров подписи в два новых GitHub Secrets.

## Сертификаты и совместимость

Новый production-сертификат создан локально: только `CN=Howl`, без страны и организации, RSA3072/SHA256. SHA256 DER: `b5068a213a65805793a2dc001423cc68dd6084a8118adb473cc37192889a3321`. Публичный сертификат — `signing/howl-2026.cer`; закрытый ключ в репозиторий не входит.

Прежний сертификат сохраняется: `8627a0876f3baf1dcf3bf7de297398fa65bc6256a8c6ef30132483995730faa7`. `KEYSTORE_BASE64` и `LOCAL_PROPERTIES` не меняются. Новый ключ предназначен для отдельных `ANDROID_ROTATION_KEYSTORE_BASE64` и `ANDROID_ROTATION_PROPERTIES`; сейчас они ещё не загружены.

- API 24–32: прежний активный signer.
- API 33+: новый signer через v3.1. В проверке SDK фактически покрываются API 24–36.
- Lineage содержит ровно два закреплённых сертификата old→new. Для прежнего явно заданы installed-data=true, permission=true, shared-uid=false, auth=false, rollback=false.
- APK и внешний файл lineage сравниваются побайтно после чтения официальной библиотекой; проверяются также сертификаты и capabilities.
- Старый `C=RU` остаётся в совместимых блоках/истории; переход не стирает его из APK и прежних выпусков. Основание: [AOSP v3.1](https://source.android.com/docs/security/features/apksigning/v3-1), [capabilities ротации](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/src/apksigner/java/com/android/apksigner/help_rotate.txt).

## Сохранение данных и следующего обновления

Файлы `app/`, manifest, applicationId `how.vpn.howl`, версии/схемы Room, формат TypedProfile и safe-state не изменялись относительно основы. Подписание дополнительно сравнивает SHA256 каждого файла ZIP до/после; исходный APK не перезаписывается инструментом. Несоответствие блокирует дальнейшую сборку.

`tools/AndroidSigning.java` использует официальный apksig из Android Build Tools 36.0.0. Приватные ключи и Java Properties читаются из окружения в память, без записи новых ключей/паролей на диск и вывода в журнал. Операции SDK для lineage используют byte buffers: стандартные readFromFile/writeToFile некоторых версий оставляют открытые handles на Windows.

Кандидат получает два разных возрастающих versionCode. Upgrade-тест использует закреплённый опубликованный APK 822, первый и следующий кандидат, настоящий PackageInstaller и два синтетических профиля. Он проверяет UID, записи Room/remoteURL, выбранный профиль и конфиги с рабочими резервами, а также запуск после каждой установки. Проверка разрешена только на свежем `howl-rotation-*` AVD; физические устройства и существующие установки отклоняются до любых изменений. Проверяются ABI и native bridge: APK только ARM, поэтому x86_64-образ должен поддерживать ARM translation. Отсутствие поддержки — ограничение окружения, не результат проверки ротации. На момент подготовки этот тест ещё не выполнялся.

Будущий `build.yml` требует сохранённую `signing/howl-2026.lineage` и новые секреты. Автоматического возврата к прежней подписи при отсутствии ключа нет: после выпуска ротации такой fallback нарушил бы следующие обновления Android 13+. Сейчас `dev` не меняется, поэтому рабочая публикация остаётся прежней.

## Уже проверено локально

- 26 Python-тестов, в том числе строгая политика сертификатов/capabilities и совпадение публичного .cer с закреплённым SHA; `diff --check`.
- Полный цикл новой production-реализации на одноразовых тестовых ключах и настоящем публичном APK: создание/повторное чтение lineage, подписание и повторное подписание, официальный ApkVerifier по каждой API 24–36, прежний signer до33 и новый с33, installed-data=true, rollback=false, точное совпадение встроенной lineage. Неверный pin, изменённый APK и перезапись исходного файла отвергаются. Рабочие ключи в этих тестах не использовались.
- Синтетические Room-базы создаются по committed-схемам; SQLite integrity и версии3/1 подтверждены локально. Реального устройства это не заменяет.
- Независимое ревью механизма подписи без открытых существенных замечаний. Тест установки отдельно проходит ревью.

## Хранение и незавершённые проверки

Новый PKCS12 защищён случайным паролем, пароль — Windows DPAPI CurrentUser. Каталоги доступны владельцу и SYSTEM. Локальный зашифрованный резерв на том же ноутбуке сверён; это **не независимая копия на другом устройстве**, DPAPI зависит от Windows-профиля. Перед публичным выпуском нужен отдельно проверенный защищённый резерв и восстановление. Старый локальный зашифрованный keystore скопирован без изменения; его соответствие действующему CI-ключу ещё не подтверждено паролем/подписью.

Автоматическая проверка отклонила объединённую команду создания и загрузки ключа в GitHub: подготовка ротации не была признана достаточным согласием на конкретную передачу приватного ключа. После этого выполнено только локальное создание; обходов передачи не было. Требуется отдельное решение владельца именно по двум новым Secrets того же репозитория `mobileproxy/howl-android`. Значения ключей/паролей в чат не нужны.

После разрешения: сохранить новые Secrets, отправить только ветку кандидата, выполнить CI без upload-artifact/Releases, сохранить публичную lineage из отчёта и проверить её SHA, зафиксировать фактические результаты upgrade/подписи. Пока не выполнены: настоящая old→new lineage, подписанный новым ключом Howl-кандидат, CI этого этапа, PackageInstaller/сохранение данных на эмуляторах/устройствах, физический VPN. Ничего не опубликовано и не установлено на ноутбуке. Бюджет Actions $0 и блокировка перерасхода не менялись.

Локальные доказательства и защищённое хранение находятся в `tools/support/android-signing-rotation-20261020/` основного рабочего каталога проекта. Приватные файлы оттуда нельзя копировать в коммиты, Actions artifacts, публичные отчёты или чат.
