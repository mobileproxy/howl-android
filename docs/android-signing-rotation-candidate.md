# Howl Android: подготовка настоящей ротации подписи

20.10.2026. Ветка `android/signing-rotation`, основа `85273d77f7c54df348ea1a6fd5fba4dfb8541704`. Проверенный код `511f0b6329180a24da1ebb825f883bb489f0dff3`. Владелец отдельно разрешил передачу нового ключа и параметров в два новых GitHub Secrets; они сохранены. [CI 39449991033](https://github.com/mobileproxy/howl-android/actions/runs/39449991033) **успешен**: подпись и сохранность данных PackageInstaller подтверждены. **Это не полная приёмка приложения: запуск, чтение профилей самим Room и реальный VPN пока не подтверждены.** Публикации нет.

## Сертификаты и совместимость

Новый production-сертификат создан локально: только `CN=Howl`, без страны и организации, RSA3072/SHA256. SHA256 DER: `b5068a213a65805793a2dc001423cc68dd6084a8118adb473cc37192889a3321`. Публичный сертификат — `signing/howl-2026.cer`; закрытый ключ в репозиторий не входит.

Прежний сертификат сохраняется: `8627a0876f3baf1dcf3bf7de297398fa65bc6256a8c6ef30132483995730faa7`. `KEYSTORE_BASE64` и `LOCAL_PROPERTIES` не менялись; их имена и даты изменения сверены через GitHub API до/после. Новый ключ сохранён в отдельных `ANDROID_ROTATION_KEYSTORE_BASE64` и `ANDROID_ROTATION_PROPERTIES`, значения в журнал/чат не выводились.

- API 24–32: прежний активный signer.
- API 33+: новый signer через v3.1. В проверке SDK фактически покрываются API 24–36.
- Lineage содержит ровно два закреплённых сертификата old→new. Для прежнего явно заданы installed-data=true, permission=true, shared-uid=false, auth=false, rollback=false.
- APK и внешний файл lineage сравниваются побайтно после чтения официальной библиотекой; проверяются также сертификаты и capabilities.
- Настоящая lineage сохранена в `signing/howl-2026.lineage`: 2138 байт, SHA256 `306164bc1f94d7a1c7ee93f1fd90a0d2f6a675491a8ba7dd964c61b6d6c30c0a`. Она повторно используется последующими сборками и не пересоздаётся молча.
- Старый `C=RU` остаётся в совместимых блоках/истории; переход не стирает его из APK и прежних выпусков. Основание: [AOSP v3.1](https://source.android.com/docs/security/features/apksigning/v3-1), [capabilities ротации](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/src/apksigner/java/com/android/apksigner/help_rotate.txt).

## Сохранение данных и следующего обновления

Файлы `app/`, manifest, applicationId `how.vpn.howl`, версии/схемы Room, формат TypedProfile и safe-state не изменялись относительно основы. Подписание дополнительно сравнивает SHA256 каждого файла ZIP до/после; исходный APK не перезаписывается инструментом. Несоответствие блокирует дальнейшую сборку.

`tools/AndroidSigning.java` использует официальный apksig из Android Build Tools 36.0.0. Приватные ключи и Java Properties читаются из окружения в память, без записи новых ключей/паролей на диск и вывода в журнал. Операции SDK для lineage используют byte buffers: стандартные readFromFile/writeToFile некоторых версий оставляют открытые handles на Windows.

Кандидат получает два разных возрастающих versionCode. Upgrade-тест использует закреплённый опубликованный APK 822, первый и следующий кандидат, настоящий PackageInstaller и два синтетических профиля. Проверяются UID, записи SQLite/remoteURL, выбранный профиль и конфиги с рабочими резервами. Проверка разрешена только на свежем `howl-rotation-*` AVD; физические устройства, установленные приложения и остаточные DATA от прежней установки отклоняются до записи. После установки обязательны наличие DATA и совпадение его владельца с UID приложения. Ошибка ADB при проверке WAL или неполный ответ прерывают приёмку, а не считаются отсутствием WAL.

В общем CI используется явный `--package-data-only`: реальные установки 822→823→824 без запуска приложения; в отчёте `acceptanceScope=package-installer-data-retention`, `appLaunchesVerified=false`, `appRoomReadVerified=false`. Это доказывает сохранение данных установщиком, но не проверяет миграцию или чтение данных кодом приложения. Без флага сохраняется строгий сценарий запуска после каждой установки; живой PID сам по себе тоже не доказывает чтение Room.

Образы выбраны по фактической поддержке ARM: Android 11/API30 и Android 15/API35, то есть старая и новая ветки подписи. Android 13/API33 Google APIs x86_64 не имеет ARM ABI/translation и отверг настоящий APK с `INSTALL_FAILED_NO_MATCHING_ABIS`. Опубликованный неизменённый 822 в ARM translation на API30 падал с SIGSEGV, на API35 один запуск прошёл, повторный завершился SIGILL в `libbox.so`. Поэтому запуск ядра исключён из доказательств, а не исправляется подменой APK, ABI-библиотек или ядра. Диагностика `.github/workflows/validate-rotation-emulators.yml` оставлена только для ручного запуска. Перед публичным выпуском нужен стабильный тест на настоящем ARM Android 13+ и старой поддерживаемой версии.

Дополнительная диагностика native ARM на стандартном macOS-runner не дала результата запуска: первый прогон остановился на непринятой SDK-license, подготовка лицензий исправлена; повторный оставался в очереди и отменён после окончания основного CI. Это **не подтверждение несовместимости ARM-эмулятора**. `.github/workflows/validate-rotation-native-arm.yml` сохранён только для ручного запуска, без секретов подписи; полноценная ARM-приёмка остаётся незавершённой.

Будущий `build.yml` требует сохранённую `signing/howl-2026.lineage` и новые секреты. Автоматического возврата к прежней подписи при отсутствии ключа нет: после выпуска ротации такой fallback нарушил бы следующие обновления Android 13+. Сейчас `dev` не меняется, поэтому рабочая публикация остаётся прежней.

## Хранение и незавершённые проверки

Новый PKCS12 защищён случайным паролем, пароль — Windows DPAPI CurrentUser. Каталоги доступны владельцу и SYSTEM. Локальный зашифрованный резерв на том же ноутбуке сверён; отдельно проверены его чтение и совпадение сертификата. Это **не независимая копия на другом устройстве**, DPAPI зависит от Windows-профиля. Перед публичным выпуском нужен отдельно проверенный защищённый резерв и восстановление. Старый локальный зашифрованный keystore скопирован без изменения; его соответствие действующему CI-ключу ещё не подтверждено паролем/подписью.

Новые Secrets сохранены по явному разрешению владельца, отправлена только ветка кандидата. Настоящие APK823/824 подписаны, проверены на API24–36 и приняты PackageInstaller на API30/35 с сохранением синтетических данных; публичная lineage сохранена, SHA сверен. Физическое устройство, запуск/чтение данных приложением и реальный VPN не подтверждены. `dev`, последний Release и его assets повторно сверены без изменений; сайт по-прежнему предлагает 1.0.4(822). Ничего не опубликовано и не установлено на ноутбуке. Workflow имеет только `contents: read`, не загружает Actions artifacts и не публикует Releases. Финальная проверка GitHub API: **0 Actions artifacts всего в Android-репозитории**, 0 у итогового run. Бюджет Actions $0 и блокировка перерасхода не менялись; страница биллинга в этой работе повторно не проверялась.

Локальные доказательства и защищённое хранение находятся в `tools/support/android-signing-rotation-20261020/` основного рабочего каталога проекта. Приватные файлы оттуда нельзя копировать в коммиты, Actions artifacts, публичные отчёты или чат.
