## Общий сценарий с Windows

Референс: Windows `windows/server-check-progress` / `ed38e4f`, `docs/step15-server-checks.md`.

| Состояние | Что видит пользователь |
|---|---|
| Queued | Ожидает проверки |
| Checking | Проверка · попытка 1/2 |
| RetryWaiting | Пауза перед повтором |
| Retrying | Проверка · попытка 2/2 |
| Working | Работает · N мс, время проверки |
| NoResponse | Нет ответа · 2 попытки; причина не установлена |
| Error | Ошибка проверки; доступность сервера не определена |
| Cancelled | Не завершено |

- До четырёх проверок одновременно; общий пул блокирующих native-вызовов также ограничен четырьмя. Каждый узел повторяется независимо от остальных. Два HTTP-адреса те же, что в Windows: Cloudflare и gstatic generate_204. Первая попытка — 6 с на адрес, повтор — 4 с, пауза — 2 с, общий предел попытки — 14 с. На границе JNI есть запас 0,5 с к таймауту RPC.
- Счётчик считает завершённые подключения, а не число адресов/попыток; повторяющиеся показаны отдельно. Финальный снимок страхует от задержанных промежуточных событий.
- Остановка сохраняет готовые результаты; повтор обрабатывает только незавершённые/неуспешные и сохраняет время успешных. Полный повтор сбрасывает старые результаты. Закрытие панели, уход приложения в фон, ручной выбор узла и остановка службы отменяют собственную проверку.
- Смена сети сбрасывает результаты и во время проверки, и между запусками. Профиль/топология/удалённая сессия инвалидируют старый снимок; удалённые группы исключаются, поздние события прежнего поколения не принимаются. Для другой удалённой сессии старый список сначала очищается.
- Список/типы протоколов берутся из потока групп работающего ядра. Автовыбор, Direct/Selector/URLTest/Reject/Block/DNS не выдаются за отдельные VPN-подключения и не входят в прогресс. Локации располагаются рядом, порядок не меняется при ответах. Полный исходный тег и название протокола сохранены; для ShadowTLS сохраняется подпись из собственного тега, поскольку ядро видит внутренний Shadowsocks.
- Общая панель прогресса закреплена над списком; карточки показываются в одну колонку, чтобы статусы/протоколы помещались. 24 общих ключа совпадают с Windows во всех шести языках; два дополнительных Android-ключа — заголовок и занятость ручной диагностики. Старые urlTestDelay/urlTestTime продолжают обновляться в модели ядра, но не рисуются свежим результатом ручной проверки.

## Вызов ядра и отмена

Используется уже присутствующий в libbox `v1.14.0-lx.29` метод `URLTestOutbound(tag, link, timeout)`: конкретный outbound или endpoint, включая WireGuard/AmneziaWG. Ядро не обновлялось, временные конфиги/сервисы не запускаются. Проверены исходники API закреплённого тега и наличие реализации в существующем ARM64 libbox.so; присутствие метода и компиляция не заменяют запуск на телефоне.

Для каждого блокирующего RPC создаётся отдельный **owned** CommandClient, привязанный к захваченному локальному/удалённому адресату. Поток групп/статуса и shared remote client не передаются транспорту. Отмена закрывает только этот собственный клиент через отдельный пул, вне Main; native-вызовы не занимают главный поток. Общий клиент и VPN-служба не отключаются. Клиент закрывается также после успешного результата/ошибки; отменённая очередь не создаёт новых клиентов. Запоздавший успешный ответ не меняет UI.

Закреплённое API использует `{delay,error}`: пустая error — успех, включая **0 мс**; этот случай не выдаётся за отказ. Непустая error означает неуспешную пробу, а транспортные исключения/неподдерживаемый RPC — отдельную ошибку проверки. Известный ответ удалённого target распознаётся по точному префиксу данного API и превращается в безопасную ошибку без исходного тега. Произвольный текст сетевых ошибок не анализируется для догадок о блокировке и не попадает в UI/отчёты.

Ручная проверка не вызывает `selectOutbound`, закрытие пользовательских соединений, reload или перезапуск VPN. Автовыбор/сторож работают по прежним правилам и могут независимо менять фактический узел. Новый ManualProbeGate исключает одновременную ручную диагностику GUI и проверку списка, но не меняет фоновые пробы сторожа.

«Работает» означает успешный проверочный HTTP-запрос через конкретный выход. Это не скорость скачивания, проверка всего DNS/TUN/правил приложений или гарантия работы всех сайтов. NoResponse не доказывает блокировку, аварию сервера или отсутствие интернета. Отмена клиента/отбрасывание результата не обещают мгновенной остановки native-кода в любой фазе установления командного канала; RPC ограничен таймаутами.
